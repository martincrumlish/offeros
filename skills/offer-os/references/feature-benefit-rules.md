# Feature-Benefit Rules

Every feature must pass the So What Test.

For each feature, write:

- what the buyer gets
- what it helps them do
- why that matters now
- which buyer problem it solves
- what proof or preview supports it
- the plain buyer-facing bullet

Weak:

- "Includes a workbook."

Strong:

- "Includes a 21-day tracker so you know which sessions are complete, which matters because race prep falls apart when effort is high but progress is invisible."

Offer-stack deliverables use the same rule. Do not list deliverables without buyer-facing value logic.
