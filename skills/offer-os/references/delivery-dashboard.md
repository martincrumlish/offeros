# Delivery Dashboard

OfferOS delivery dashboards are browser-based asset hubs for presenting and using the completed offer system. They are not just file lists.

This is different from a customer portal. The required v2 dashboard is for the seller/student/workshop demo: it previews and opens every asset generated by OfferOS. If the offer itself needs a customer portal or fulfillment dashboard, create that as an additional artifact.

## Required Behavior

The dashboard should let the user access and preview:

- sales page
- sales copy
- design guide
- PDF product
- logo
- sales page graphics
- Facebook ad copy/strategy
- Facebook ad images
- email sequence
- VSL deck
- VSL browser-safe preview
- QA notes
- image provenance and commercial audit status when useful

## Preview Standard

Use the standard OfferOS v2 modal dashboard template. Generate it with `scripts/generate_delivery_dashboard.py`, then theme the CSS from `design.md` if needed. Do not hand-roll a static dashboard layout for each offer.

Preview behavior:

- HTML pages open in a large modal iframe.
- Images open in a large modal image viewer.
- PDFs open in an iframe when the browser supports it.
- PPTX files should use a browser-safe fallback, usually rendered slide images, contact sheet, or PDF export.
- Every modal should still provide a direct open/download action.
- The page should include `data-offeros-dashboard="v2-modal"` so QA can verify the standard structure.

## Visual Standard

The dashboard should follow the resolved `design.md`. If no design exists, use a clean operational layout with strong hierarchy and restrained decoration.

Avoid:

- linking users away for every asset
- replacing the modal/iframe dashboard with a static link grid
- tiny thumbnails with no preview
- owner-only notes in customer/demo dashboards
- generic unbranded file index pages

## Manifest Integration

Read from `offer-os.json` when available. Register artifact id, type, category, title, path, preview path, status, provenance, and quality scores.

Useful artifact types:

- `page`
- `document`
- `image`
- `pdf`
- `deck`
- `email`
- `ad`
- `source`

## Validation

Verify:

- all linked files exist
- images load
- modals open
- iframes load where supported
- no horizontal overflow on mobile
- PPTX has a browser-safe preview path
- dashboard contains the v2 modal marker, artifact cards with `data-path` and `data-preview`, and iframe/modal preview code
- visual fallbacks are labeled honestly
- the dashboard makes QA status clear instead of hiding commercial failures
